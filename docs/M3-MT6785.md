# M3 — the MT6785 (begonia) device layer

The method is the common tree's
[`docs/mtk-porting.md`](https://github.com/oosexgang/hakios-xnu-kernel/blob/mtk/docs/mtk-porting.md),
applied to this phone. The kernel, GICv3, PSCI, the loader's return path and the
run cycle are shared; what is begonia's is the table below and the drivers the
common MT6768 tree does not have (touch, GPU generation, UFS-free storage).

**Rule:** a line in `device.conf` moves to `works` only after it is seen on the
phone. The values here are read from the running Linux (live device tree,
`/proc/iomem`, `/sys`), not guessed from the vendor source.

## Constants read from this phone

| What | Value | Where it came from |
|---|---|---|
| Kernel entry (LK) | `0x40080000` | `/proc/iomem` (`Kernel code`), boot image v2 |
| RAM | `0x40000000` + `0x180000000` (6 GiB, top `0x1c0000000`) | `memory/reg` |
| ramoops console | `0x4d09f000`, `0x40000` | cmdline `ramoops.*`, `mblock-13-pstore` |
| ramoops pmsg | `0x4d0e0000`, `0x10000` (request at `+0xf000`) | same |
| pstore dump | `0x4d010000`, `0xe0000` | `mblock-13-pstore` |
| Framebuffer | `0x7d9b0000`, `0x2250000` | `mblock-15-framebuffer/reg`; fb0 stride 4320, 1080x2340 |
| XNU physical window | `0xc0000000` + `0x94000000` (M2 hello) | chosen clear of LK/Image/ramdisk/ramoops/fb |
| GIC | GICD `0x0c000000`/`0x40000`, GICR `0x0c040000`/`0x200000` | `soc/interrupt-controller@c000000` |
| UART | `0x11002000` (mt6577-uart) | `soc/serial@11002000` |
| eMMC (UFS phone: not used) | MSDC0 `0x11230000` | `soc/mmc@11230000` |
| microSD (XNU/logs) | MSDC1 `0x11240000`, pad `0x11e10000` | `soc/mmc@11240000`, `mmc1` alias |
| Touch | Novatek **NT36672A**, SPI `0x11019000`, CS 0 | `soc/spi@11019000/touchscreen@0` |
| Backlight | TI LM36274 at I²C `0x11007000`, addr `0x11` | `backlight` alias |
| Display engine | OVL0 `0x14008000`, OVL-2L `0x14009000`/`0x1400a000`, RDMA0 `0x1400b000`, mutex `0x14016000`, DSI `0x14014000`, DSI-PHY `0x11e50000` | live DT aliases + nodes |
| GPU | Mali-G76 (Bifrost) `0x13040000` | `soc/gpu@13040000` |
| CONNSYS (Wi-Fi/BT) | `0x18002000` + the register set in `reg` | `soc/consys@18002000` |
| PMIC / charger | MT6359 + MT6360 | `mt6359.dtsi`, I²C nodes |
| CPU | 2x A76 (6,7) + 6x A55 (0-5) | `cpus`, `/proc/cpuinfo` |

The display driver's OVL offsets in the Linux `mtk_disp_ovl.c` match the
loader's constants (`SRC_CON 0x02c`, `CON(n) 0x030+0x20n`, `PITCH 0x044+0x20n`,
`ADDR 0xf40+0x20n`); the *base* is begonia's `0x14008000`, and the loader probes
all OVL/RDMA bases to find the layer LK left the framebuffer on. The mutex
(`0x14016000`) is **not touched** by the M2 loader: the MT6768 addresses in the
reference (`0x14001020/24`) are not begonia's, and a wrong write there can hit
another block. M3 probes the mutex layout before using it; the OVL change is
applied by the next frame.

## Order of work (each needs the previous on the phone)

1. **M1 on hardware** — `fastboot boot /tmp/begonia-m2-nopayload.img`; Linux
   still boots; the ramoops capture shows the loader banner.
2. **The request loop** — `tools/request-xnu.sh --no-reboot` + reboot; the
   loader consumes `DARWIN-BEGONIA:BOOT-XNU`.
3. **XNU hello** — `fastboot boot /tmp/begonia-m2-hello.img`; the loader copies
   the Mach-O, builds the tree/boot_args, runs XNU with `cpus=1`, returns, and
   the log says the kernel version and `Hello from user space on Darwin!`.
4. **Timers/GIC** — if it idles at "waiting for the root", check
   `ICC_CTLR_EL1.EOImode` (the MT6768 pitfall) and use `-DTIMER_PROBE=1`.
5. **Memory** — move from the M2 2.3 GiB window to a window clear of the
   reserved holes (`0xf9e00000..0xffefffff`, `0x1b8600000..0x1bfffefff`), likely
   `0x100000000` + ~2.8 GiB, before loading the iOS system image in DRAM.
6. **Display** — the framebuffer is LK's; confirm the OVL probe writes the
   right block and that alpha-off makes XNU's console visible.
7. **Touch** — the NT36672A is an SPI Novatek, not the TD4160 TCM the common
   tree uploads firmware to; write a small `redwood_nt36672a.c` and probe from
   the loader first (no kernel rebuild per cycle).
8. **Storage** — M2 reads `xnusys` from the SD through MSDC1 into DRAM; for iOS
   either keep that (fits the 2.5 GB image in a clear window) or write an
   MSDC1 XNU block driver (`emmc_root=1` equivalent).
9. **GPU** — Mali-G76 MC4, Bifrost; the MT6768 tree targets another Mali
   generation, so treat `redwood_mali.c` as a reference, not a drop-in.
10. **Radios/battery/camera** — CONNSYS is at `0x18002000`; the MT6768 driver
    is the starting point (the phone's own firmware, not redistributed).

## What is already in this repository

- `mtkloader/mtkloader-begonia.bin`: MT6785 constants, MSDC1 GPT reader, OVL
  probe, raw pmsg request, XNU payload and return-to-Linux.
- `xnuloader/`: `mkpayload.py` and the example identity (the real identity
  comes from the operator's IPSW).
- `tools/m2-chain.sh`: Linux boot image + loader + `XNUP` payload, with the
  64 MiB and payload-integrity checks.
- `linux/hakios_ramoops.ko`: the M1/M2 log and request path from Linux.

Not in this repository: Apple user space, the IPSW, vendor firmware, or any
secret. iOS activation and Apple services are out of scope.
